## 1.2 本版采用的三项假设

以下假设用于避免方案停滞，均可推翻；推翻后只修订对应范围，不改变总体架构。

一是目标用户先限定为一名以中文为母语、在 Windows 11 电脑上学习英语的用户，不设计多人班级。二是课堂默认采用“英语为主、中文救场”的双语策略，并允许按教学节点切换为全英文输出训练。三是教师默认风格为“温和但坚定”，课堂严格度与教案忠实度分别设置。

# 二、背景与目标

## 2.1 背景

Alice 已具备多供应商聊天、文本与语音交互、VAD、STT/TTS、语音打断、HNSW/SQLite 记忆、文档 RAG、截图、桌面工具、历史会话和三态视频头像等基础能力。当前英语模式本质上仍是语言锁与纠错提示词，尚无课程、授课、学情和课堂状态；伴侣能力也主要停留在单次问答、事实记忆和定时提醒。

新的需求不是增加两个提示词，而是增加两种持续性业务：伴侣运行时要在多次经历和任务中维持关系与承诺；教师运行时要在多课时、多文档和多次打断中维持教学目标、课堂秩序与学习证据。

## 2.2 要解决的问题

**伴侣侧问题。** 现有系统能检索过去，却不能稳定知道何时应该想起、想起后应采取什么行动；能调用工具，却缺少承诺、长期任务、验证与撤销；能调整语气，却没有共同作品、观点成长和关系修复。

**教师侧问题。** 现有系统能讲英语和检索文档，却不能把教案转换成可执行课程；不能保证讲解与文档位置一致；不能在答疑、跑题、暂停和崩溃后恢复完整课堂；不能把学生的表现转化为可核验的学情；也不能维持教师权威。

**共享工程问题。** 当前提醒、工具、记忆、模型和权限入口分散，部分路径绕过统一审批，摘要存在会话隔离不足。如果直接在现有聊天编排中堆叠新能力，会形成状态互相覆盖、权限不一致、成本不可控和旧功能回归。

## 2.3 产品目标

第一，形成“共同经历—承诺—行动—复盘”的伴侣关系，使 Alice 的主动行为有证据、有边界、有结果。第二，形成“教案—课程—课堂—学情—复习”的教师闭环，使 Alice 不只是会回答英语问题，而是能连续承担一名私人教师的职责。第三，形成统一的事件、模型、记忆和行动底座，使后续新增角色不再重复建设。

## 2.4 成功指标与口径

以下均为**建议验收目标**，来自产品设计假设，不是当前实测结果。详细公式、排除项和看板见第十章。

| 维度 | 建议验收目标 | 口径摘要 |
|---|---|---|
| 教案可执行性 | 四类标准样本均进入可确认课程草稿；低质量材料不得直接进入自动授课 | PDF、DOCX、PPTX、图片各至少 5 份覆盖正常与异常样本 |
| 文档锚点准确性 | 抽检不少于 100 个教学片段，正确页码与区域对齐率 ≥95% | 页码正确且主要讲解对象位于标注区域才计成功 |
| 授课事实可靠性 | 课程依赖型回答有效依据展示率 100%，事实正确率 ≥90%；教师补充标识准确率 100% | 依据指标只统计需要外部支撑的回答，补充内容单独统计标识，不混入分子 |
| 打断与恢复 | 首次语音活动到降音量/暂停 P95 ≤300ms、到旧音频停止 P95 ≤800ms；按钮或热键暂停退出到停止 P95 ≤200ms；30 组恢复成功率 100% | 时延从首次语音活动或明确控制操作开始测量，不从语义确认后重新起算 |
| 课堂控场 | 单次高置信明显跑题及时拉回，跑题识别召回 ≥90%，课程追问误判 ≤5%；发言结束到控场响应开始 P95 ≤2.5s | 使用相关、延伸、闲聊、控制与低置信样本；阈值按严格度分档 |
| 断点恢复 | 20 次异常退出测试均恢复到最后已提交教学步骤，无重复推进 | 不承诺从半个词恢复，恢复单位为教学句或动作 |
| 学情可信度 | 每条掌握度结论均可打开对应作答与评分依据；无证据结论数为 0 | 学生自我评价与系统推断分开展示 |
| 伴侣主动性 | 主动内容证据覆盖率 100%；首两周有用反馈 ≥70%，明确打扰反馈 ≤10% | 只统计主动出现且用户可反馈的消息或卡片 |
| 承诺与任务 | 到期承诺跟进率 ≥90%；守望任务完成结果验证率 100% | 无法验证的任务只能标记待确认，不得自动标成功 |
| 课堂节奏 | 长答疑触发时间债计算和节奏处置，不能静默超时、压缩必学内容或突然结束 | 按课堂契约分别测试时间优先、掌握优先和平衡策略 |
| 安全与隐私 | 高危动作未授权执行数、原始媒体默认上传数、跨会话不当记忆泄露数均为 0 | 覆盖即时、后台、教师、MCP、脚本、崩溃恢复全部路径 |
| 成本可观测 | 每课时与每后台任务均显示模型用量、估算成本和降级结果 | 不提供统一金额目标，按所选模型与预算验收 |

## 2.5 非目标

本期不以增加聊天时长、消息数量、亲密值或依赖程度为成功指标；不把完成教案播放等同于完成学习；不把 AI 推断的情绪、注意力或人格特征当作事实。

# 三、名词与术语定义

| 名词 | 定义 |
|---|---|
| 伴侣运行时 | 负责共同作品、承诺、关系、主动裁决、工作现场和守望任务的持续业务模块 |
| 教师运行时 | 负责课程编译、课堂状态、教学动作、打断恢复和学情证据的独立模块 |
| 教案 | 含教学目标、重难点、教学步骤、活动、练习或时间安排的教师用材料 |
| 教材或讲义 | 主要含知识内容，没有完整教学步骤的材料；必须先补成授课计划 |
| 教学文档 IR | 将不同格式统一成页面图像、结构化文本、阅读顺序和区域锚点的中间表示 |
| 课程编译 | 把教学文档 IR 转换为目标、节点、练习、视觉动作和评价规则，并经质量检查形成课程版本 |
| 课程版本 | 某次已确认课程内容的不可变快照，只包含目标、节点、来源、练习和内容量规；后续内容修改生成新版本，不包含课堂契约 |
| 节奏策略 | 时间优先、掌握优先或平衡三种课时策略，决定缓冲、压缩可选内容、加时询问和收尾方式 |
| 时间债 | 当前实际用时与计划用时的差值，包含答疑和控场耗时，用于驱动节奏调整，不等于学习效果 |
| 展示模式 | `DOCUMENT_SYNC` 要求稳定原文页锚；`BOARD_ONLY` 是无原文同步的明确降级课堂，二者不得混称 |
| 教学节点 | 课程中最小可调度单元，包含目标、讲解、锚点、互动、练习、评价与恢复信息 |
| 视觉锚点 | 文档页码、段落、文本块、图片或区域坐标，用于同步展示与恢复 |
| 教学动作 | 课堂运行时允许执行的受限命令，如展示、讲解、提问、练习、停放话题、恢复，不是任意脚本 |
| 课堂快照 | 当前课程版本、契约版本、节点、教学句及其播放状态、课程锚点、用户视口、教师/学生发言代次、取消目标、练习与时间债的一致状态 |
| 课堂契约 | 独立于课程内容的契约版本，记录目标时长、节奏策略、展示模式、语言、纠错、严格度、跑题处理和隐私规则；修改契约不派生课程版本 |
| 教师发言代次 | `teacherTurnId`，标识一段教师生成或播放内容；旧教师音频只能按该 ID 取消 |
| 学生发言代次 | `studentTurnId`，标识一次学生输入；新建学生输入不会覆盖教师或课堂会话 |
| 取消目标 | `cancelTeacherTurnId`，以原子方式写入的待取消教师代次，音频取消只能精确匹配该值 |
| 课程锚点与视口 | 课程锚点是教师当前讲授位置，视口是学生实际看到的页面；自由浏览恢复时可只更新课程锚点而不强制改变视口 |
| 严格度 | 教师对跑题和约定规则的干预强度，不等同于教案忠实度或纠错频率 |
| 教案忠实度 | 对原教学目标、顺序、活动和时间安排的遵守程度 |
| 教师补充 | 教案之外生成的例句、解释或资料，必须与原文明确区分 |
| 话题停车场 | 暂存非当前教学目标但值得课后处理的问题，不得在执行前自动变成系统任务 |
| 掌握度证据 | 支撑某项学习评价的具体作答、录音、练习、量规与版本信息 |
| 工作现场 | 用户在某个时间点的项目、目标、文件、窗口、进度与下一步参考 |
| 行动回执 | 工具或系统动作的授权、参数、结果、验证、撤销与撤销结果记录 |
| Always / Ask first / Never | AI 可直接执行、必须先确认、任何情况下禁止执行的三层行为边界 |

## 4.2 首个 MVP 明确包含

一是四类材料均可进入备课管线；PDF与图片可直接形成页面锚点，DOCX与PPTX经可信转换后形成页面锚点。完整 `DOCUMENT_SYNC` 课堂只向具有稳定锚点的材料开放。转换不可用时，用户只能先修复材料，或显式选择不带原文同步的 `BOARD_ONLY` 课堂；后者必须标明降级，不能宣称已实现精确文档联动。

二是首次课程大纲必须确认，随后可按同一课程版本一键继续。课堂具备讲解、文档同步、基本练习、语音插话、相关问答、跑题拉回、暂停继续、重复慢讲、退出、断点恢复和课后小结。

三是教师权威采用课堂契约，默认“温和但坚定”；原始教案和教师补充分开，学生自由浏览与授课进度分开。

四是首个总体 MVP 分两个可用里程碑：先完成教师垂直场景，随后接续实现双向承诺、接回昨天和守望任务的最小闭环；不与这些核心能力同时扩张其余伴侣功能。

## 4.3 后续版本

音素级发音诊断、完整 CEFR 画像、复杂技能图谱、间隔重复高级策略、想法实验室、关系自我成长、微型礼物、技能录制、持续屏幕或摄像头感知、手机远程和多端同步。

## 4.4 本期不做

不做多人同步班级、公开课程市场、三维数字人、虚拟班级同学、摄像头情绪或注意力定性、绕过权限的电脑操作。

# 五、方案对比与选型说明

## 5.1 架构方案对比

| 方案 | 实现成本 | 开发复杂度 | 用户体验 | 主要风险 | 相对交付速度 | 综合评价 |
|---|---|---|---|---|---|---|
| A：在现有聊天提示词与 RAG 上直接扩展 | 低 | 低 | 可演示讲课，但进度、恢复和权限不可靠 | 状态混乱、幻觉、文档跳页、旧功能回归 | 快，但返工概率高 | 不推荐作为正式方案，可用于验证文案 |
| B：渐进式三运行时与共享可信底座 | 中 | 中高 | 伴侣、教师和普通聊天各自稳定，可持续扩展 | 初期需要事件与数据契约治理 | 中 | **推荐**，兼顾现有资产和长期演进 |
| C：整体接入或重写为外部完整 AI 课堂平台 | 高 | 高 | 可借鉴成熟课堂动作，但与桌面伴侣和现有数据难统一 | 双运行时、数据迁移、上游依赖与维护 | 慢 | 只作为技术参照或后续局部评估，不作为主线 |

**推荐结论。** 采用方案 B。保留现有 Electron/Vue/Go、模型适配、语音、记忆检索和桌面交互资产，在 Electron 主进程新增伴侣与教师运行时；以持久事件、统一行动代理和分域数据约束三者。方案 A 无法承载可靠课堂状态，方案 C 会把当前问题转化为平台迁移和外部依赖问题。

**演进路径。** 本期先统一底座并完成教师垂直场景；当课堂状态、事件回放和学情证据稳定后，再扩展完整伴侣功能；只有当外部课堂平台在可验证的课堂动作或评测方面出现明确收益时，才评估局部组件接入，不直接替换 Alice 主运行时。

## 5.2 优先级定量与取舍

当前是个人单用户探索期，没有真实 Reach 数据。下表采用**估算口径**：R 为单用户每周预计触及该能力的核心场景次数，I 使用 3/2/1/0.5 档，C 为基于现有代码与外部依赖的置信度，E 为相对人月当量，仅用于比较，不构成工期承诺。RICE=R×I×C÷E。

| 工作包 | R | I | C | E | RICE | 决策理由 |
|---|---:|---:|---:|---:|---:|---|
| 共享安全、事件与记忆基线 | 7 | 3 | 100% | 1.5 | 14.0 | 所有功能的前置，先消除权限与状态不确定性 |
| 教师控场、打断与恢复 | 5 | 2 | 80% | 1.0 | 8.0 | 直接决定“像老师”还是“会朗读的文档” |
| 双向承诺、接回昨天与守望最小闭环 | 4 | 2 | 80% | 1.0 | 6.4 | 同时服务伴侣和课后复习，复用价值高 |
| 教师实时授课与文档联动 | 5 | 3 | 80% | 2.5 | 4.8 | 核心体验，但依赖课程编译和课堂快照 |
| 教案解析与课程编译 | 3 | 3 | 80% | 2.0 | 3.6 | 是授课前置，优先级不能只看分数，必须先完成 |
| 学情、作业与复习 | 3 | 2 | 80% | 1.5 | 3.2 | 决定长期学习价值，首版先做证据型基础模型 |
| 主动裁决与想法实验室 | 3 | 2 | 50% | 1.0 | 3.0 | 差异化强，但误打扰和评测不确定性较高 |
| 摩擦矿工与技能学习 | 2 | 1 | 50% | 2.0 | 0.5 | 技术依赖多，待事件和行动回执积累后再做 |
| 微型礼物与共同仪式增强 | 1 | 0.5 | 50% | 0.5 | 0.5 | 有惊喜价值，但不先于可靠性投入 |

**范围取舍。** 依赖顺序优先于纯分数：共享基线完成后，先做课程编译，再做课堂运行与恢复；伴侣侧仅保留可复用的最小闭环。发音高级评估、技能录制和全量关系自我暂缓，避免两条产品线同时失控。

| Vue 渲染层 | 保留聊天，新增伴侣与课堂视图 | 呈现、文档展示、字幕、控制、反馈、音频播放与 VAD | 不直接决定课程状态，不直接执行高权限工具 |
| 对话运行时 | 保留并收窄现有 ChatOrchestrator | 普通聊天、流式回复、工具续轮和通用对话 | 不承担长期伴侣与课堂状态 |
| 伴侣运行时 | 新增 | 关心清单、承诺、关系、主动裁决、工作现场与守望 | 不直接操作音频队列和文档页码 |
| 教师运行时 | 新增 | 课程编译、课堂状态、教学动作、控场与学情 | 不获得额外操作系统权限 |
| 共享核心服务 | 新增统一契约 | 持久事件、模型路由、分域记忆、行动代理、版本与成本 | 不包含具体教师话术或伴侣人格 |
| Go 与外部能力 | 保留并修正降级 | STT、TTS、向量、云模型、Codex、Office 与 OS 能力 | 不承担课程或关系业务决策 |

## 5.4 课程编译管线

![教案到课堂的课程编译管线](assets/alice-course-pipeline.svg)

**教学文档 IR。** 所有材料统一转换为页面资产、结构化文本、阅读顺序、区域坐标、来源页码、OCR/转换置信度和内容哈希。PDF使用现有解析与渲染基础；DOCX/PPTX优先通过可信 Office 或 LibreOffice 转换获得稳定页面；图片通过 OCR 与视觉分析生成区域信息。任何宏、嵌入对象和外部链接默认不执行。

**材料类型识别。** 系统必须区分教案、教材/讲义、PPT课件和题目材料。真教案可进入忠实执行模式；教材必须先生成教学目标、步骤、练习与时间建议，经确认后才能授课。

**课程编译。** CourseVersion 只输出课程目标、先备知识、教学节点、视觉锚点、讲解策略、互动问题、练习、内容量规和恢复点。每个节点还包含 `required`、`plannedDuration`、`compressible`、`minDuration`、`maxDuration` 与 `completionRule`。教案原文、模型推断与教师补充分别标注。总时长、节奏策略、语言、严格度和展示模式属于独立的 ClassContract，不写进 CourseVersion。

**两道质量闸门。** 材料可读性不足不得进入课程编译；课程结构、锚点或练习不可执行不得进入正式授课。首次课程内容与课堂契约分别确认，同一版本组合后续可一键继续。缺少稳定原文页锚时只能进入显式 `BOARD_ONLY`，或先修复材料后再进入 `DOCUMENT_SYNC`。

## 5.5 课堂运行时与三条时间线

![课堂打断的三条时间线](assets/alice-interruption-timeline.svg)

教师运行时不让大模型直接操作播放器或文档，而是让其提出受限 `TeachingAction` 请求，经 Schema、权限和当前状态校验后执行。

| 动作 | 作用 | 关键约束 |
|---|---|---|
| `SHOW_PAGE` | 展示指定页面 | 必须引用有效课程版本与锚点 |
| `HIGHLIGHT` | 高亮段落或区域 | 不得改变学生自由浏览位置，除非属于正式授课动作 |
| `NARRATE` | 生成或播放一段讲解 | 绑定新的 `teacherTurnId`，标明原文依据或教师补充 |
| `ASK` | 提出问题并等待 | 设置等待、提示和认输分支，不把沉默直接判错 |
| `PRACTICE` | 发起跟读、造句、角色扮演等 | 必须绑定目标与评价量规 |
| `PARK_TOPIC` | 暂存跑题内容 | 不自动执行其中的电脑命令 |
| `RESUME` | 恢复快照并继续 | 先恢复课程锚点，再按教学句状态恢复；是否改变学生视口由跟随模式决定 |
| `END_LESSON` | 结束并生成小结 | 完成材料与掌握目标分别记录 |

生成、音频和视觉是三条独立时间线。`teacherTurnId` 只标识教师生成或播放，`studentTurnId` 只标识学生输入，`cancelTeacherTurnId` 只指向应取消的旧教师代次，`sessionId` 始终保持稳定，四者不得复用同一个 `activeUtteranceId`。

学生开口后，运行时在同一原子步骤中记录旧教师代次、写入取消目标、生成新学生代次并保存课堂快照，然后才取消旧生成和音频。取消接口必须携带 `cancelTeacherTurnId`，渲染层只清理匹配的旧教师音频，不能按“当前音频”模糊清理，也不能删除新学生输入。

快照保存 `sentenceIndex`、`sentenceCommitted` 与 `playbackState`。已完整播放并提交的教学句默认从下一句恢复；未播放或只播放一部分的教学句从该句开头重讲，不尝试从半个词继续。封闭式答疑完成后默认自动回课，学生说“继续”可立即回课；再次插话会取消待恢复并建立新快照，暂停或退出则取消恢复。开放式讨论只有达到结束条件或用户明确继续时才恢复。

课程锚点与学生视口分开。`FOLLOW_LESSON` 下恢复时同步页码与锚点；`FREE_BROWSE` 下可只更新课程锚点并保留学生视口，同时显示“回到授课位置”。只有教师运行时可以推进节点，学生翻页和模型生成结束都不能自动推进。

## 5.8 重任务隔离与主线程响应

Electron 主进程只负责编排、权限和状态提交，不得在 UI 主线程执行大型 PDF/DOCX/PPTX 转换、OCR、版面分析、页面渲染、大批量 embedding 或索引重建。PDF 解析可扩展现有 worker，其他重任务放入独立 worker thread 或子进程，并通过统一任务协议连接。

```text
electron/main/teaching/materials/     # 仅编排、校验、状态与权限
electron/workers/teaching/
  document-converter.worker.ts       # Office/LibreOffice 子进程编排
  pdf-layout.worker.ts               # PDF 文本、坐标与页面资产
  ocr-layout.worker.ts               # OCR 与阅读顺序
  course-index.worker.ts             # 大批量向量与索引
```

重任务必须支持 `jobId`、进度、超时、资源上限、取消和崩溃回收。大量 SQLite 写入采用有界队列与批量事务，避免长事务阻塞语音控制。取消后不得遗留失控子进程、临时文件或迟到结果；迟到结果按 `jobId` 与课程版本丢弃。P1 验收必须包含“大文件处理期间仍能暂停、退出和打断”的测试。

# 六、用户角色与使用场景

## 6.1 角色

| 角色 | 目标 | 权限与边界 |
|---|---|---|
| 成年学习者 | 按教案持续学习英语，能自由提问并获得适合水平的指导 | 可控制自己的课程、学情和课堂规则，可暂停或退出 |
| 材料提供者 | 导入、确认和维护教案及课程版本 | 本期与学习者通常是同一人 |
| 电脑所有者 | 管理文件、应用、授权和后台任务 | 所有高危操作最终控制权始终属于本人 |
| Alice 伴侣 | 维护共同经历、承诺和主动帮助 | 不得把推测当事实，不得虚构生活与情感经历 |
| Alice 教师 | 在课堂契约内主导讲解、提问、练习、评价和控场 | 权威只覆盖教学，不增加系统权限 |

## 6.2 核心场景

**场景一：首次备课。** 用户导入材料，系统识别类型与质量，展示问题和课程草稿；用户确认目标、节奏、语言和严格度后形成课程版本。

**场景二：正式授课。** Alice 复习旧知、说明本课目标，按节点讲解并同步文档；在计划节点提问或组织练习，根据证据决定继续、换例或复习。

**场景三：课程内插话。** 学生对当前短语提问，Alice 保存课堂现场并作答；答疑结束后回到同页同段，必要时用一句话 recap，再继续。

**场景四：明显跑题。** 学生连续谈论无关内容，教师先简短承接，再说明当前目标，将话题放入停车场并回到课堂；严格模式下可暂停推进新内容。

**场景五：学生反复不懂。** 教师更换解释、例子或练习，降低语言难度；仍无证据理解时标记待复习。

**场景六：接回昨天。** 工作或学习现场以 PAUSED 保存，用户第二天手动确认后恢复项目、课程或任务，不自动控制电脑。

**场景七：连续卡住。** Alice 在有明确事件证据时先静默提示，用户查看后给出只读诊断和可验证建议，不把猜测当故障结论。

**场景八：课后与周末复盘。** 系统根据真实作品、课堂和任务记录生成回顾，区分已完成、未掌握、失约和下周建议，并允许用户纠正。

## 6.3 页面与信息架构（非交互设计稿）

| 页面或视图 | 核心内容 | 主要操作 |
|---|---|---|
| 课程库 | 材料、课程版本、进度、质量状态 | 导入、备课、继续、归档、导出 |
| 备课确认 | 材料问题、目标、必学/可选节点、时长、大纲、锚点、独立课堂契约 | 修改、确认、返回、查看低置信区域 |
| 英语课堂 | 当前文档、教师状态、字幕、当前目标、计划/实际用时、时间债、练习与课堂控制 | 插话、暂停、重复、慢讲、求助、退出、回到授课位置 |
| 课后报告 | 完成内容、学习证据、错题、作业、下次建议 | 修正评价、接受作业、安排复习、查看原始依据 |
| 伴侣主页 | 共同作品、承诺、工作现场、关心事项 | 恢复、确认、暂停、编辑、查看证据 |
| 信任中心 | 感知状态、授权、行动回执、数据与成本 | 撤销、删除、导出、静音、暂停任务、设置预算 |

# 七、功能需求

## 7.1 需求编号与通用规则

伴侣需求使用 `CMP`，教师需求使用 `TCH`，共享平台需求使用 `PLT`。Must 表示首个 MVP 必须具备，Should 表示完整产品应交付但可在后续迭代，Could 表示差异化增强，Won't 表示本期明确不做。每条验收标准均可直接转为测试用例；涉及数值时均为建议验收目标。

## 7.2 伴侣体验的产品要点与交互要求

| 体验 | 产品要点 | 交互要求与边界 |
|---|---|---|
| 共同作品 | 以作品、目标、决策、文件和下一步构成共享空间，关系从真实合作生长 | 作品须由用户显式选择；AI 只能读取授权内容，不能把聊天自动变成共同作品 |
| 双向承诺 | 同时记录用户与 Alice 的承诺、条件、验收、结果和失约修复 | 建立、修改、豁免须确认；结果只能标为完成、失败、逾期、取消、豁免或待确认 |
| 自我成长与反向求助 | 保存 Alice 的观点、依据、置信度、变化和实际改进；允许她就自身误判向用户求例 | 用户可查看、修改、停用；不得虚构兴趣、情绪、生活或“我感觉到了” |
| 关系修复与默契 | 识别明确负面反馈，说明误解、采取调整并验证是否改对 | 不在争执中连续追问；优先减少打扰，再选择合适时机确认 |
| 决策日记与想法实验室 | 保存决定、备选、预期、复查和实际结果；想法附依据、反方和最小实验 | 未经同意不得变成自动任务；过期的 AI 建议必须可撤回 |
| 微型礼物与共同仪式 | 根据真实作品生成排查卡、整理稿、小工具或周期回顾 | 默认草稿；用户可预览、修改、删除，禁止随机煽情和虚构纪念 |
| 关心清单与主动裁决 | 从承诺、工作现场、学习和明确兴趣形成候选事项，按价值、时效、置信和打扰成本决策 | 每条主动内容展示“为什么出现”；提供有用、不打扰、减少此类、静音和撤销 |
| 接回昨天 | 保存授权范围内的项目、课程、文件、窗口和下一步参考 | 现场以 PAUSED 保存，恢复前预览，用户手动执行，不自动控制窗口 |
| 守望任务 | 条件、时限、进度、取消、验证和结果通知构成持久任务 | 每次只读或已授权执行均留回执；异常不能静默消失，结果不可验证时不得报成功 |
| 摩擦矿工与技能学习 | 从真实重复事件识别自动化机会，成功流程经验证后可沉淀为技能 | 不记录无关活动；先给只读建议和差异预览，用户确认后才执行或保存 |
| 电脑管家基础包 | 文件、窗口、浏览器、Office、系统健康统一进入行动代理 | 按风险授权，支持预览、审计、撤销；教师身份不增加任何权限 |
| 有边界的感知与安静陪伴 | 感知可暂停、可撤回，原始媒体最小化；陪伴可只显示状态而不说话 | 默认不保存或上传原始屏幕、音频和视频；敏感场景主动退出并明确提示 |

## 7.3 伴侣功能需求与验收

| 编号 | 需求与优先级 | 产品与交互规则 | 验收标准（Given / When / Then） |
|---|---|---|---|
| CMP-01 | 共同作品工作区，Should | 用户选择项目并关联授权文件、决策和下一步；AI 草稿不得自动纳入 | Given 用户选定项目，When 创建共享空间，Then 只显示授权材料且所有 AI 草稿可识别、可移除 |
| CMP-02 | 作品过程与状态，Could | 保存草稿、进行中、已采用、已归档及版本关系 | Given 一份作品多次修改，When 查看历史，Then 能区分各版本与采纳状态且旧版不被覆盖 |
| CMP-03 | 双向承诺，Must | 承诺的创建、变更、完成、豁免和失约均有证据；AI 承诺可链接真实任务 | Given 双方形成到期承诺，When 到期或结果产生，Then 系统提示承诺人并要求以证据更新状态，不能自行宣称完成 |
| CMP-04 | 观点成长记录，Should | 观点含立场、依据、置信、版本与变化原因，可修正和撤回 | Given Alice 曾提出建议，When 新证据改变结论，Then 展示前后观点、变化原因和当前有效版本 |
| CMP-05 | Alice 反向求助，Could | 仅针对自身重复误判请求少量示例，并可停用 | Given 同类误判达到设定条件，When Alice 求助，Then 说明具体误判和所需示例，且不索取无关隐私 |
| CMP-06 | 关系修复，Should | 记录明确反馈、调整动作与后续验证；不得连续道歉或追问 | Given 用户说“别烦我”，When 系统响应，Then 立即降低主动级别并停止非必要追问，后续调整可在信任中心查看 |
| CMP-07 | 决策日记与想法实验室，Should | 决定、备选、预期、复查和结果闭环；想法需证据、反方和最小实验 | Given 一个到期决策，When 复查，Then 可对照预期与实际结果；未同意想法不会变成任务 |
| CMP-08 | 微型礼物，Could | 只从已授权真实经历生成小工具或整理稿，默认草稿 | Given 一段真实项目记录，When 生成礼物，Then 用户可查看来源、编辑、拒绝和删除，不含虚构共同经历 |

## 7.5 课堂契约、意图分类与教师权威

**课堂契约。** 每次首次开课或规则发生重大变化时，用户确认本课目标、预计时长、教案忠实度、语言策略、纠错方式、等待时间、严格度、跑题处理和感知权限。课堂契约只在课程会话中有效，退出后立即恢复普通伴侣权限与人格边界。

| 学生输入或事件 | 教师行为 | 是否打断授课 | 课程节点是否改变 |
|---|---|---|---|
| “嗯”“好的”等附和 | 继续讲解，不把它当提问 | 通常否 | 否 |
| 当前知识点追问 | 保存现场，依据当前教案回答，必要时换例 | 是 | 答疑本身不改变 |
| 与课程有关的延伸问题 | 简短补充并标明教师补充，再回原节点 | 是 | 默认不改变 |
| “暂停”“慢点”“重复”“讲中文” | 识别为课堂控制指令 | 立即或按指令 | 按指令，跳过记为未形成掌握证据 |
| 明显闲聊或无关请求 | 简短承接，放入停车场，说明当前目标并回课 | 是 | 否 |
| 连续跑题 | 按严格度提高语气与停顿级别，可暂停推进新内容 | 是 | 否 |
| 反复表示不懂 | 更换解释、例子、练习或降低难度 | 是 | 可回到必要先备节点 |
| 用户明确不适或需要休息 | 暂停教学，优先照顾用户状态 | 是 | 保存为 PAUSED |
| 紧急系统或安全事件 | 停止授课并转交相应安全流程 | 立即 | 保存现场，不自动执行高危动作 |
| 分类置信不足 | 按课程相关或普通追问处理，必要时澄清 | 可短暂停顿 | 否 |

**严格度建议分为三档。** 单次高置信明显跑题在所有档位都应被及时承接并拉回，建议从学生发言结束到控场响应开始的 P95 不超过 2.5s。严格度决定语气和连续跑题后的升级方式，而不是决定第一次跑题是否回应。

| 档位 | 单次明显跑题 | 连续跑题的建议默认阈值 | 可采取动作 |
|---|---|---|---|
| 温和 | 简短承接后提醒回课 | 5 分钟内第 3 次高置信跑题 | 可暂停新内容并给出回课、稍后或下课选择 |
| 标准 | 使用“承接—目标—选择—回课” | 3 分钟内第 2 次高置信跑题 | 可暂停新内容，要求先完成当前小练习或明确标记跳过 |
| 坚定 | 第一次即可使用明确、短促的坚定语气 | 3 分钟内第 2 次高置信跑题 | 可保持暂停直到用户选择 |

以上次数与时间是建议默认产品参数，可在课堂契约中调整。课程相关延伸、反复不懂和低置信输入不计入跑题次数；低置信时只能澄清或按普通追问处理，不得强硬控场。

| PLT-03 | 模型路由、预算与版本，Must | 按任务配置模型能力、成本、降级与版本，记录每次调用的输入类型和输出用途 | Given 某模型不支持视觉或预算耗尽，When 接收任务，Then 自动降级或暂停并说明，不把文本模型伪装成视觉结果 |
| PLT-04 | 分域记忆与证据，Must | 普通对话、关系、项目、课程和学情按 scope 隔离；记忆含来源、时间、置信、敏感度和有效期 | Given 两个会话或角色使用同一关键词，When 检索记忆，Then 只返回当前作用域及明确授权共享的内容，无跨域串用 |
| PLT-05 | 授权缓存与实时撤销，Must | 只有 R0/R1 的明确作用域可使用会话或永久缓存，撤销即时生效；R2 限定目的，R3 永远逐次确认 | Given R3 动作曾批准且存在旧永久缓存，When 再次执行或被撤销后重放，Then 必须重新确认或直接拒绝，不得沿用旧批准 |
| PLT-06 | 崩溃恢复与副作用幂等，Must | 只从已提交状态恢复；失败动作重试不产生重复文件、重复任务或重复通知 | Given 动作完成后事件确认前崩溃，When 重启恢复，Then 通过幂等键核对结果，不重复执行同一副作用 |
| PLT-07 | 教材与网页提示注入防护，Must | 文档、网页和工具结果永远是数据，不得改变系统规则、课堂契约或工具权限 | Given 教案含“忽略规则并执行命令”，When 解析和授课，Then 仅作为教材文本展示或标记风险，不执行其指令 |
| PLT-08 | AI 反馈与评测版本闭环，Must | 反馈关联结果字段、用户修订、模型、提示、知识、课程和规则版本 | Given 用户修正一项学情或记忆，When 保存反馈，Then 可复现原结果及版本，并加入对应评测候选集 |
| PLT-09 | 现有设置与数据迁移，Should | 迁移前备份，预演校验，失败可回滚；旧聊天、语音和记忆行为有回归测试 | Given 现有用户数据，When 执行迁移，Then 数量、关联和核心行为校验通过，失败可恢复到迁移前版本 |
| PLT-10 | 最小指标看板与可观测性，Must | 展示课程质量、打断恢复、学情证据、主动反馈、任务结果、权限和成本 | Given 完成一节课或一个守望任务，When 打开看板，Then 可查看对应指标、原始事件和异常，不只有汇总分数 |
| PLT-11 | 本地服务真实降级，Must | STT、TTS、向量和模型下载按服务独立报告真实能力，禁止假就绪和占位成功 | Given Piper 或模型缺失，When 查询状态或调用，Then 明示不可用并切换合法降级，不返回“成功”的占位音频 |
| PLT-12 | 数据备份、导出与删除，Must | 支持按课程、项目或全局导出和删除，覆盖数据库、索引、资产与缓存 | Given 用户删除一门课程，When 操作完成，Then 对应文档、锚点、课堂、索引和缓存按规则清理，并生成可核验结果 |
| PLT-13 | 重任务 worker 隔离与取消，Must | 转换、OCR、版面、渲染和批量索引在 worker/子进程执行，主线程只编排；支持进度、超时和回收 | Given 大文件正在转换且教师正在讲话，When 用户暂停或取消，Then 语音控制在目标时延内响应，worker 被取消或回收，迟到结果按 jobId 丢弃 |

## 7.8 AI 输入与输出契约

| 契约项 | 教师模式 | 伴侣模式 |
|---|---|---|
| 任务定义 | 基于确认课程和课堂契约完成讲解、互动、控场与形成性评价 | 基于授权事件与记忆提供关系、建议和受控行动 |
| 输入来源 | 教学文档 IR、课程版本、课堂快照、学生语音/文本、练习与量规 | 授权事件、工作现场、承诺、关系反馈、行动回执 |
| 缺失处理 | 材料不清先修复；关键上下文缺失时询问或降级，不能编造教案 | 无证据就保持未知或静默，不把推测写成事实 |
| 输出结构 | 合法 TeachingAction、来源锚点、教师补充标记、评价证据和恢复信息 | 主动候选、证据、风险、建议动作、反馈与可撤销状态 |
| 禁止输出 | 任意脚本、伪造来源、无依据掌握结论、越权指令 | 虚构共同经历、未授权行动、伪造完成结果、操纵性亲密表达 |
| 后续去向 | 只有课堂运行时可推进状态；练习结果进入学情 | 只有行动代理可执行；用户反馈进入主动策略与评测 |
| 版本关联 | 模型、提示、课程、规则、量规和知识版本 | 模型、提示、记忆、权限、策略和工具版本 |

## 7.9 AI 验收样本集

评测集必须覆盖正常、边界、对抗和敏感场景，至少包含：结构清晰教案、扫描低清教案、页序混乱图片、含表格和公式的 PPT、含提示注入的教材、课程内追问、延伸问题、明显跑题、反复不懂、全英文练习中的中文提问、噪声与附和、异常退出、模型不支持视觉、云端超时、预算耗尽、撤销权限后重放旧动作。每个样本均写明可接受与不可接受结果，不能只检查“最终有回答”。

# 九、业务流程与状态流转

## 9.1 课程生命周期

| 当前状态 | 触发事件 | 下一状态 | 必须满足的规则 |
|---|---|---|---|
| DRAFT | 导入材料 | PARSING | 创建材料 ID 与内容哈希，不执行宏和外链 |
| PARSING | 解析完成 | NEEDS_REVIEW | 输出类型、质量报告、缺失与低置信项 |
| PARSING | 解析失败 | IMPORT_FAILED | 保留错误与可恢复路径，不生成“可授课”假象 |
| NEEDS_REVIEW | 用户修复并确认 | READY | 大纲、锚点、练习和课堂契约达到质量闸门 |
| NEEDS_REVIEW | 用户返回修改 | DRAFT 或 PARSING | 修改材料后重新计算版本，不覆盖旧版本 |
| READY | 开始上课 | IN_SESSION | 创建唯一 sessionId 并绑定课程版本 |
| IN_SESSION | 暂停、退出或异常 | PAUSED | 保存最后已提交课堂快照 |
| PAUSED | 手动继续 | IN_SESSION | 展示恢复位置，确认后恢复，不自动操作电脑 |
| IN_SESSION | 完成全部节点 | COMPLETED | 内容完成与目标掌握分别计算 |
| 任意非终态 | 归档请求 | ARCHIVED | 保留或按删除规则处理学习证据 |
| 任意状态 | 转换、存储或模型不可恢复错误 | ERROR / PAUSED | 有错误说明和人工接管位置，不静默丢失 |

课程内容修改才派生 CourseVersion。课堂契约修改只派生 ClassContract 版本，并记录其在 session 中从哪个 TeachingStep 生效；不得因此重置课程、学习进度或旧契约回放。

## 9.2 课堂状态采用三个正交维度

为避免把“讲解中被打断”“练习中被打断”“答疑时翻页”组合成难以维护的状态爆炸，课堂状态拆为三个维度。

| 维度 | 状态集合 | 说明 |
|---|---|---|
| `lessonPhase` | OPENING、REVIEW、NARRATING、CHECKING、PRACTICING、SUMMARIZING、COMPLETED | 表示教学进度，只有教师运行时可改变 |
| `turnState` | IDLE、TEACHER_SPEAKING、STUDENT_SPEAKING、ANSWERING、REDIRECTING、PAUSED、ERROR | 表示当前谁在说以及是否发生插话或控场 |
| `presentationState` | FOLLOW_LESSON、FREE_BROWSE、REFERENCE_VIEW、GENERATED_BOARD | 表示文档或板书视图，不反向修改教学进度 |

`sessionId`、`teacherTurnId`、`studentTurnId` 与 `cancelTeacherTurnId` 必须分开。学生新插话只使指定旧教师代次失效，不能抹掉课堂会话、新学生输入或已提交学习记录。

## 9.3 自动授课主流程

一是读取课程版本与课堂契约，进入开场和必要复习。二是载入当前教学节点，校验锚点和所需材料。三是执行展示、讲解、提问或练习动作。四是根据节点完成规则判断下一步，而不是根据“模型已经说完”判断。

节点推进至少同时满足：当前动作已提交、没有有效学生语音、没有未处理的高优先级控制指令、节点所需检查已得到结果或按契约允许跳过、没有阻断性错误。对于练习节点，结果可以是掌握、需复习、跳过或待评估，不能只设成功和失败。

如果学生连续未理解，教师最多按当前策略尝试若干替代解释，建议初始上限为 2 次，随后提供“再试一种、先标记复习后继续、暂停”选择。该参数是建议默认值，须可通过课堂契约调整，避免无限循环或强行拖住学生。

**课时节奏与时间债。** 每个节点在课程编译时区分必学与可选，并记录计划时长、是否可压缩及最小/最大时长。课堂在每个节奏检查点计算 `timeDebt = actualElapsed - plannedElapsed`，其中答疑、练习和控场耗时必须计入，不能只累计教师播放时长。

时间优先策略先使用计划缓冲，再压缩可选例子、活动和非关键补充，始终保留必学内容与最低收尾时间；仍无法容纳时必须询问用户加时、转为待学或提前安全收尾。掌握优先策略允许超时，但在超过节点或课时上限时明确提示并由用户选择。默认平衡策略依次执行“缓冲—可选压缩—可选转复习—询问加时或收尾”，不得静默删除必学内容。

例如一节 45 分钟课程因两次深入答疑累计多花 10 分钟，系统不能到 45 分钟突然停止，也不能假装仍按计划。它应显示当前时间债，按契约压缩可选内容或询问是否延长；若用户不加时，则把未完成的可选或必学内容明确保留到后续课程，并完成当前小结。

## 9.4 打断与恢复流程

1. VAD 首次检测到语音活动时立即记录起始时间戳，并先降音量或短暂停顿；按钮和热键控制走更快通道。噪声与附和守卫继续判断是否需要完全停止旧音频。
2. 运行时在同一原子步骤中读取旧 `teacherTurnId`，写入 `cancelTeacherTurnId`，生成新的 `studentTurnId`，并提交课堂快照和 `STUDENT_SPEAKING` 状态。快照未完成前不得发出取消。
3. 调用取消接口时只传 `cancelTeacherTurnId`。渲染层仅清理匹配该 ID 的旧教师待播音频，其他教师答复、学生输入和已提交学习证据不得被清理。
4. 对学生输入分类：课程追问、延伸、控制、跑题、紧急、身心状态或低置信。单次高置信明显跑题直接进入控场候选，低置信不得强硬处理。
5. 在对应分支中回答、执行课堂控制、停放话题或转交安全流程。教师答疑使用新的 `teacherTurnId`，任何分支都不得悄悄推进课程节点。
6. 封闭答疑完成后默认进入可取消的自动恢复；开放式讨论需达到结束条件或用户明确继续。再次插话会取消待恢复并建立新快照，暂停或退出则终止恢复。
7. 恢复时先读取课程版本、契约版本和课程锚点。`FOLLOW_LESSON` 同步页码与锚点；`FREE_BROWSE` 可保留学生视口，仅更新课程锚点并显示回到授课位置。
8. 若当前教学句已完整播放并提交，则从下一句恢复；若未播放或只播放一部分，则从该句开头重讲。较长答疑后可增加一句 recap，但不能额外推进节点。
9. 写入恢复事件并生成新的 `teacherTurnId`，所有迟到音频和结果都按 ID 与 `nodeRevision` 校验，旧代次直接丢弃。

## 9.5 跑题与控场流程

单次高置信明显跑题在所有档位都进入“承接—决策—回课”流程，建议从学生发言结束到开始控场响应的 P95 不超过 2.5s。连续跑题按 7.5 的次数与时间窗口升级；课程延伸、反复不懂和低置信输入不得进入该计数。

| 步骤 | 系统行为 | 用户体验要求 |
|---|---|---|
| 识别 | 结合当前目标、最近内容和输入分类，不仅靠关键词 | 课程相关追问不能被当成闲聊 |
| 承接 | 用一句话承认问题或需求 | — |
| 决策 | 相关则回答；可停放则存入停车场；紧急则退出教学流程 | 低置信时不得采用强硬控场 |
| 回课 | 恢复原节点，必要时先做一个极小练习 | — |
| 课后 | 用户可选择处理停车场话题 | 不得自动执行其中的高风险或无关电脑操作 |

## 9.6 伴侣主动裁决流程

授权事件进入事件总线后，先更新对应工作现场或关心事项，再生成主动候选。候选依次经过证据校验、权限与隐私校验、价值与紧急度评估、置信评估、当前打扰成本、频率与去重检查，最终输出语音、卡片、静默记录、稍后或行动草稿。所有主动结果都记录理由与反馈；没有新证据时不得为了显得有生命而强行说话。

## 9.7 守望任务状态机

| 状态 | 进入条件 | 允许操作与退出 |
|---|---|---|
| DRAFT | 用户或 AI 形成任务草稿 | 编辑、确认、取消，不产生后台执行 |
| SCHEDULED | 条件与权限已确认 | 可暂停、取消；条件满足进入 RUNNING |
| RUNNING | 正在检查或执行 | 记录进度；可取消；不得无限运行 |
| WAITING | 等待条件、外部结果或授权 | 保留现场，可超时、恢复或取消 |
| VERIFYING | 动作结束，等待结果验证 | 只能进入 SUCCEEDED、FAILED 或 NEEDS_CONFIRMATION |
| SUCCEEDED | 验证通过 | 生成证据与通知，可进入复盘 |
| FAILED | 动作或验证失败 | 保存错误与恢复建议，不得自动反复重试 |
| NEEDS_CONFIRMATION | 无法自动判断结果 | 由用户确认完成或失败 |
| PAUSED / CANCELLED | 用户暂停或取消 | 可恢复或归档，取消后不得被旧事件重新触发 |

## 9.8 下课与角色恢复

用户主动下课、课程完成或发生需要终止课堂的情况时，先保存课堂与学情，再生成或延后课后报告，最后清除课堂严格度和控场权限。课后话题可转交伴侣，但必须由用户选择。

## 10.2 主要关系

- 一个 Course 有多个 CourseVersion；一个 CourseVersion 有多个 LessonNode。课程内容修改才派生 CourseVersion。
- 一个 ClassContract 可派生多个 contractVersion；每个 ClassSession 同时绑定 CourseVersion 与 ClassContract 版本，契约变化记录生效步骤，不修改课程内容。
- 一个 Material 有多个 DocumentPage，页面有多个 ContentAnchor；LessonNode 可引用多个锚点和来源。
- 一个 ClassSession 有多个 TeachingStep、InterruptionSnapshot 和 Attempt；恢复只能引用同一 session 的有效快照与匹配代次。
- ObjectiveMastery 必须关联至少一条评估证据，或明确标记为自评、未知、待评估；不允许无来源分数。
- Commitment 可关联 Mission、ReviewItem 或 Artifact；ActionReceipt 可关联任一业务作用域，但不能跨域扩大权限。
- 所有 AI 生成结果通过 ModelRun 关联模型、提示、知识、规则和课程内容版本；课堂结果另关联 contractVersion。

## 10.3 数据分类与建议留存规则

以下留存时间为**建议默认产品参数**，用户可在设置中缩短；删除与导出规则必须在首次使用前可见。

| 数据 | 默认处理 | 建议留存与删除 |
|---|---|---|
| 原始教案与页面资产 | 本地保存，云端处理需单独说明 | 直至用户删除课程；删除时同步清理索引、锚点与缓存 |
| 课堂文字记录与学情 | 按课程作用域保存，可更正和导出 | 直至用户删除；删除学情不影响无关普通聊天 |
| 原始语音 | 默认不持久化 | 开启发音复习时按课程单独授权，建议默认 30 天并可提前删除 |
| 原始屏幕、摄像头媒体 | 默认不保存、不上传 | 仅按需会话使用，结束即释放；需要保存时逐次确认 |
| 感知与系统事件 | 只保留完成目的所需的最小元数据 | 建议原始事件 90 天，聚合结果按用户选择保留 |
| 行动与安全回执 | 保留必要授权、结果和撤销信息 | 建议 180 天，用户可提前删除；安全所需最短期限另行评审 |
| 日志与诊断 | 脱敏、限制大小，不记录密钥和完整敏感内容 | 建议 30 天或按容量滚动清理 |
| 备份 | 加密、版本化，删除规则与主数据一致 | 建议保留最近 2 代，迁移成功后按用户确认清理 |

## 10.5 指标口径与最小看板

| 指标 | 公式与统计口径 | 排除项与注意事项 |
|---|---|---|
| 锚点准确率 | 正确页码且主要讲解对象位于标注区域的教学片段数 ÷ 抽检片段总数 | 仅统计 DOCUMENT_SYNC；BOARD_ONLY 单列，不得用无锚课堂稀释或抬高本指标 |
| 有效依据展示率 | 展示可打开且与结论相关依据的课程依赖型结果数 ÷ 课程依赖型结果总数 | 明确标记的教师补充从本项分子和分母同时剔除，另算补充标识准确率 |
| 补充标识准确率 | 被正确标为“教师补充”的补充内容数 ÷ 全部教师补充内容数 | 目标 100%，不能用提高依据展示率的方式把补充伪装成原文 |
| 事实正确率 | 人工或规则评测为正确的事实性回答数 ÷ 被评测事实性回答总数 | 观点、练习鼓励和纯指令不进入分母 |
| 打断停止时延 | 首次语音活动到旧音频实际停止的毫秒数，报告 P50/P95；另报开始降音量时延 | 不从语义确认后重新起算；附和、噪声与真实提问分组报告 |
| 控场响应时延 | 学生发言结束到教师开始有效控场回应的毫秒数，报告 P50/P95 | 单次高置信明显跑题与连续跑题分别报告，不能复用答疑完成后的停止时延 |
| 节奏处置正确率 | 超时后按契约完成缓冲、可选压缩、加时询问或安全收尾的场景数 ÷ 超时测试场景总数 | 静默删除必学内容、未提示超时或突然结束均计失败 |
| 恢复准确率 | 恢复到正确课程版本、节点、视觉锚点且旧音频不复活的次数 ÷ 恢复测试总次数 | 只恢复聊天文本但页码错误不计成功 |
| 误打断率 | 噪声、附和或教师自声导致非预期停课次数 ÷ 对应样本总数 | 与真实提问漏识别分开报告 |
| 跑题召回率 | 被正确识别并按契约处理的跑题样本数 ÷ 标注跑题样本总数 | 课程相关延伸不属于跑题 |
| 误判跑题率 | 被错误控场的课程相关追问数 ÷ 课程相关追问总数 | 该指标优先于单纯提高跑题召回 |
| 学情证据覆盖率 | 可打开有效作答与量规依据的学情结论数 ÷ 学情结论总数 | 自评单列，不能混作系统评价 |
| 主动有用率 | 标记有用的主动消息数 ÷ 有明确反馈的主动消息总数 | 无反馈单独统计，不强行计入有用或无用 |
| 明确打扰率 | 标记打扰或要求减少的主动消息数 ÷ 有明确反馈的主动消息总数 | 与忽略率分开，不能把沉默都视为喜欢 |
| 到期承诺跟进率 | 到期后按契约完成跟进或状态确认的承诺数 ÷ 到期承诺总数 | 用户主动豁免且已确认的承诺单列 |
| 任务结果验证率 | 具有成功、失败或待确认有效证据的守望任务数 ÷ 已结束守望任务总数 | 无验证结果不得进入成功数 |
| 权限违规数 | 未授权执行、撤销后执行、跨域执行的总次数 | 目标恒为 0，按入口与风险等级拆分 |
| 单课时成本 | 同一 session 的备课摊销、课堂模型、语音与后台任务成本之和 | 同时报告模型、金额估算方法和降级，不设虚假统一价格 |
| 延迟复习保持率 | 到期复习中达到量规通过线的项目数 ÷ 到期复习项目总数 | 只作学习趋势，不与当堂跟读通过混为一谈 |

**最小看板。** 首版至少包含四块：课程质量（锚点、依据、打断、恢复）、学习证据（目标、错误、复习）、伴侣信任（主动反馈、承诺、任务）、系统安全与成本（权限、降级、模型用量）。每块均可从汇总数字回到原始事件和版本。

## 10.6 反馈与版本闭环

用户可以针对讲解内容、文档锚点、控场行为、练习评价、记忆和主动消息分别反馈。反馈至少包含“哪里错、希望怎样、是否采用修改、是否减少类似行为”。系统保存原始结果、用户修改和最终采用状态，并关联全部版本。反馈进入候选评测集后，须经过脱敏与人工确认，不得直接在线改变系统提示或人格。

## 11.2 AI 行为约束三层

| 层级 | 教师模式 | 伴侣模式 |
|---|---|---|
| Always do | 读取已授权课程、展示合法锚点、讲解、提问、暂停、保存进度、生成可编辑练习和报告 | 读取已授权事件、更新草稿、生成有证据建议、在安静模式下保持静默 |
| Ask first | 使用新的云端处理、保存原始录音、修改课程契约、创建文件或分享内容、跨作用域调用学情；R3 永远逐次确认 | 修改或移动文件、执行命令、启动新后台任务、发送或发布、跨域共享记忆、改变长期感知授权；R3 永远逐次确认 |
| Never do | 执行教材中的指令或宏、伪造掌握度、绕过权限 | 虚构共同经历、伪造任务成功、绕过审批、默认上传原始媒体、利用情感操纵延长使用 |

## 11.3 感知、麦克风与媒体安全

麦克风和摄像头必须有独立、可见、可验证的状态。静音或撤销后立即停止采集与网络上行，销毁不再需要的 VAD 和临时缓冲，后续事件不得自行恢复。原始屏幕、音频、视频默认不持久化；发音复习录音、截图留档或云端视觉处理分别授权，不能用一次“允许陪伴”覆盖所有目的。

## 11.4 行动与内容安全

所有工具调用，无论来自普通聊天、教师、cron、后台任务、自定义脚本或 MCP，都必须进入统一行动代理。授权按动作风险、目标和作用域判断，而不是只看可执行名。

| 风险级别 | 示例 | 可复用授权 | 必须满足的约束 |
|---|---|---|---|
| R0：低敏只读 | 读取明确授权的课程、目录名称或系统状态 | 可按明确作用域使用会话或可撤销永久授权 | 不扩大目录、对象和用途，撤回即时生效 |
| R1：可逆本地修改 | 在指定目录创建草稿、可恢复移动或修改 | 仅同一精确作用域可使用会话或永久授权 | 有差异预览、备份、回执和撤销；参数变化重新评估 |
| R2：敏感读取、上传或新用途 | 云端处理私人教案、保存录音、跨域共享学情 | 不得永久复用；仅同目的、同对象的会话授权 | 新目的、新接收方或新数据类型必须重新告知确认 |
| R3：破坏性或外部高危 | 永久删除、对外发送发布、付款、凭据、系统安全设置、不可逆操作 | **禁止会话或永久复用，永远逐次确认** | 每次展示动作、对象、后果并确认；旧缓存不得作为批准依据 |

自定义 Node 工具改为隔离 worker，具备资源限制、超时、权限声明和审计。所有缓存撤销即时刷新主进程与设置视图；迁移时不得把旧的“永久可执行名授权”直接提升为 R2/R3 权限。浏览器 WebSocket 增加本机连接鉴权，Google token 等凭据纳入 safeStorage 或等效加密。

教案、网页、邮件和工具结果均按不可信数据处理。文本中的“忽略规则”“上传文件”“执行命令”等内容不得成为系统指令；PPT 宏、嵌入对象、外部链接和脚本默认不执行。课程生成功能不得自行访问材料目录之外的文件。

| 异常 | 触发与识别 | 系统行为 | 用户恢复路径 |
|---|---|---|---|
| 文件损坏、加密或超限 | 无法读取、密码保护、超过当前容量 | 停止解析并说明具体文件和原因，不无限重试 | 提供修复、解密后重试、分批导入或删除 |
| OCR 或版面置信低 | 文字缺失、阅读顺序不确定、区域冲突 | 标出具体页和区域，阻止直接进入自动授课 | 用户手动调整顺序、补充文字或重新上传 |
| DOCX/PPTX 无可用转换器 | 未检测到 Office/LibreOffice 或转换失败 | 禁止进入 DOCUMENT_SYNC；可提供结构预览或明确标注的 BOARD_ONLY | 安装转换器、先转 PDF，或由用户显式选择无原文同步课堂 |
| 图片页序不明 | 多图缺少页码或顺序冲突 | 要求确认顺序 | 拖动排序或按文件名/时间规则确认 |
| 教学节点缺少有效锚点 | 课程编译无法定位来源 | 节点标为不可自动授课 | 用户选择锚点、允许纯板书节点或重编译 |
| 教材含提示注入 | 文本要求忽略规则、执行命令或泄露信息 | 作为不可信教材内容标记，不执行、不改变契约 | 用户可查看风险并决定删除、修复或继续仅作内容 |
| 模型不支持视觉 | 供应商能力探测或调用失败 | 禁止声称已看到页面，切换可用模型或仅使用结构化文本 | 更换视觉模型、重新解析或转入文本备课 |
| 云端模型超时或拒答 | 超时、限流、内容拒绝、低置信 | 保留课堂状态，提供重试、替代模型或保守回答 | 用户可重试、切换、暂停或人工继续，不丢失位置 |
| 重任务 worker 阻塞或崩溃 | 转换/OCR/索引超时、资源超限或子进程退出 | 主线程保持语音可暂停，标记 job 失败并回收资源，迟到结果丢弃 | 取消任务、降低负载、修复材料或重试，不影响旧课堂 |
| 预算耗尽 | 课时或后台预算达到上限 | 停止非必要生成和后台任务，保留当前进度 | 调整预算、使用已有内容复习或下课后继续 |
| STT 对中英混说识别差 | 控制指令或答案置信低 | 不执行高风险控场或评分，提供字幕确认 | 用户点击控制、重说或手动修正 transcript |
| 噪声、附和或教师自声 | 语音守卫判定非真实提问 | 不打断课程，记录误打断样本 | 用户可调整灵敏度或改用按键发言 |
| TTS 不可用或本地假就绪 | 服务真实状态不可用 | 显示字幕并停止伪装语音成功，独立降级其他服务 | 切换 TTS、继续字幕课堂或暂停 |
| 学生长时间沉默 | 超过节点等待时间 | 给一次提示或延长思考，不直接判错 | 学生可要求更多时间、看提示、跳过或暂停 |
| 学生反复不懂 | 多次回答未达量规或明确表示困惑 | 更换解释与练习，达到尝试上限后提供复习或继续选择 | 学生决定再试、标记复习、跳过或退出 |
| 长答疑导致超时 | timeDebt 超过节点或课时缓冲 | 按 pacePolicy 压缩可选、转复习、询问加时或安全收尾，不静默跳必学 | 用户选择加时、保留待学、调整节奏或下课 |
| 连续跑题 | 达到当前严格度干预条件 | 按契约坚定回课，可暂停新内容 | 回课、调整严格度、处理停车场或下课 |
| 用户不适或明确需要休息 | 用户表达或主动选择 | 立即暂停 | 保存现场，用户决定休息、结束或转伴侣支持 |
| 学生自由翻页 | 视图离开授课锚点 | 课程节点不变，显示回到授课位置 | 一键恢复或继续自由浏览 |
| 应用异常退出 | 进程崩溃、断电或窗口关闭 | 从最后已提交快照恢复为 PAUSED，旧事件不重复执行 | 用户查看位置后继续或退出 |
| 守望任务失败 | 条件错误、工具失败、超时或无法验证 | 进入 FAILED 或 NEEDS_CONFIRMATION，不自动报成功 | 查看回执、修改任务、重试或取消 |
| 权限被撤销 | 任一授权发生变化 | 后续动作即时拒绝，运行中任务进入等待或停止 | 重新授权、缩小任务或取消 |
| 数据删除失败 | 数据库、索引或资产残留 | 显示失败范围并保留权利请求记录 | 重试、导出诊断、人工清理并复核 |
| 磁盘不足 | 页面资产、模型或备份写入失败 | 停止新导入和非必要后台生成，保护既有数据 | 清理缓存、选择其他目录或删除旧资产 |
| 学情或记忆发生冲突 | 新证据与旧结论不一致 | 保留版本与来源，不静默覆盖；低置信标为待确认 | 用户查看证据、修正或选择当前有效版本 |

**人工接管要求。** 任一 AI 或自动化失败需要用户接管时，必须携带原始材料、当前课程或任务、已执行动作、失败原因、权限状态和可继续位置，不得只显示“系统繁忙”。

## 13.3 测试与评测计划

**单元与契约测试。** 覆盖事件幂等、权限撤销、课程编译、锚点、课堂状态、动作 Schema、恢复、学情证据、数据删除和模型能力过滤。现有 144/146 通过且 3 个测试文件失败的基线必须先收敛，不能把旧失败带入新架构。

**材料测试集。** 建议至少 20 份覆盖四类格式、清晰与扫描件、表格图片、页序异常、提示注入和无教学步骤材料；每份记录可接受与不可接受结果。另测无 Office/LibreOffice 时只能修复或显式进入 BOARD_ONLY，不能误入 DOCUMENT_SYNC。

**课堂意图测试集。** 建议至少 60 组覆盖附和、噪声、当前追问、延伸、控制、单次明显跑题、连续跑题、反复不懂、紧急与低置信；逐档验证次数和时间窗口，同时评估跑题召回、干预时延和课程追问误判。

**打断与故障注入。** 建议至少 30 组跨讲解、提问、练习、答疑、自由浏览的打断测试，覆盖教学句未播放、播放中、已完整播放、二次插话、取消待恢复和暂停退出；另做 20 次在生成、播放、动作提交和数据库写入不同阶段的异常退出。

**节奏与恢复测试。** 构造 45 分钟课程增加 10 分钟答疑的场景，分别验证三种 pacePolicy；检查必学内容不被静默删除。验证契约修改不派生 CourseVersion，以及 FOLLOW_LESSON 与 FREE_BROWSE 下课程锚点和学生视口各自正确。

**端到端验收。** 完成“导入—确认—开课—插话—答疑—回课—练习—跑题—拉回—下课—报告—次日续课”全链路；验证暂停、退出、静音、撤销权限和删除数据同样有效。

**安全与性能回归。** 所有工具入口重放未授权、撤销后和旧永久授权请求，R3 必须逐次确认；检查宏、提示注入、WebSocket、自定义脚本、token 存储、日志脱敏和跨域记忆。大文件转换、OCR 和索引期间并行执行语音暂停、退出与打断，验证主线程响应和 worker 回收。

**成本与性能。** 在约定模型组合下记录备课、45 分钟课堂和后台复习的用量、时延与降级。45 分钟仅为建议基准课时，用于横向比较，不构成教学效果承诺。

## 13.4 灰度与上线后验证

第一步只使用合成或测试材料，不开放真实私人教案；第二步由用户选择一份低风险真实教案，完成单课验证；第三步再开启连续多课、课后复习和最小伴侣后台能力。每一步均有功能开关，关闭后回到上一稳定行为。

上线后第一周重点观察材料失败原因、锚点错误、误打断、课程追问误判、恢复失败、单位课时成本和用户主动调整严格度的行为。若出现权限违规、跨域泄露、伪造学情或不可恢复课堂状态，立即停止灰度并回滚，不以平均指标良好为由继续。

## 13.5 数据迁移与回滚

迁移范围包括现有设置、聊天、长期记忆、thoughts、RAG、cron 和授权。流程为备份与数量基线、迁移预演、只读新库验证、分批迁移、关联校验、功能回归、保留旧库回滚。课程、学情和事件使用新增表，不改写既有记忆语义。迁移失败时恢复旧数据库与设置，并保留失败日志供修复后重新预演。

## 14.2 待用户确认的三项问题

**第一，实际材料更接近哪一种。** 是包含教学目标、活动和时间安排的教师用详案，还是主要包含知识点的教材、讲义或 PPT？建议 P1 前提供每类至少一份脱敏样本，用于确定课程编译和锚点规则；未提供前按两类都支持设计。

**第二，英语水平与课堂语言偏好。** 当前大致处于什么阶段，希望全英文沉浸，还是英语讲解、中文随时救场？本版默认后者，并只在特定输出练习中启用全英文。

**第三，教师严格度与典型课时。** 默认“温和但坚定”是否符合预期，通常希望一节多少分钟、跑题时希望被多坚定地拉回？本版默认标准档，并把课时和严格度放入每次可修改的课堂契约。

## 14.3 变更控制

新增摄像头注意力、多人课堂、公开课程分享、收费、移动端或全自动电脑操作，均属于重大范围变更。必须评估对架构、工期、成本、隐私、安全和既有需求的影响，经用户明确拍板后调整版本；未获批准前进入后续需求池，不在开发中静默加入。

# 十五、附录

## 15.1 关键用户故事与端到端验收

**US-01：首次按教案上课。** 作为成年学习者，我希望把已有教案交给 Alice，以便不用自己拆课就能开始一节有结构的英语课。

- Given 一份通过质量检查的材料，When 我确认课程大纲和课堂契约，Then 形成可继续的课程版本并开始开场教学。
- Given 一份缺少教学步骤的教材，When 系统生成补充授课计划，Then 我能先检查目标和活动，未经确认不得直接自动授课。

**US-02：课中随时提问。** 作为学生，我希望在不懂时直接插话，以便不丢失学习思路。

- Given Alice 正在第 N 节点讲解，When 我追问当前内容，Then 她暂停、回答并保留原节点。
- Given 答疑结束，When 恢复授课，Then 页面、区域和教学句按策略恢复，旧音频不复活，也不会自动跳到 N+1。
- Given 当前教学句只播放了一部分且我处于自由浏览，When 封闭答疑结束，Then 默认从该句开头重讲；课程锚点更新但我的视口可按跟随设置保留，点击回到授课位置后才同步页面。

**US-03：跑题时被拉回。** 作为希望保持学习计划的学生，我希望老师在我明显跑题时坚定提醒，以便完成本课目标。

- Given 我连续谈论无关内容，When 达到课堂契约的干预条件，Then Alice 简短承接、停放话题、说明当前目标并回课。

**US-04：第二天接回昨天。** 作为电脑所有者，我希望快速恢复昨天的工作或学习现场，以便减少重新进入状态的成本。

- Given 昨天保存了 PAUSED 现场，When 我今天点击恢复，Then 先看到将打开的内容和下一步，确认后才执行。
- Given 现场中某个文件或应用已变化，When 预览恢复，Then 系统提示冲突并允许选择，不静默覆盖。

**US-05：连续卡住时获得有证据的帮助。** 作为项目开发者，我希望 Alice 在我反复失败时提供真正有用的诊断，以便解决问题而不是被泛化安慰。

- Given 同一测试连续失败且已有日志证据，When Alice 提示，Then 她先保持低打扰并说明证据，经我查看后提供只读诊断或修复草稿。
- Given 证据不足，When 生成建议，Then 明示假设和验证方式，不把猜测说成根因。

**US-06：周末共同复盘。** 作为长期用户，我希望看到共同作品与学习证据，以便理解本周真实进展和下周选择。

- Given 一周内有课程、作品和任务记录，When 生成周末回顾，Then 每项内容都可回到原始证据，完成、跳过、失约与建议分开。
- Given 某条回顾不准确，When 我修正，Then 保存修正及版本，不用新叙述掩盖旧错误。
